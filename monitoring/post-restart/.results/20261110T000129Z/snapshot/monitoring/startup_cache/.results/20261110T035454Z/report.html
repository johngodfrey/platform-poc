Dependencies, local registry, ingress and monitoring remain warm. Worker creation is outside the clock. Cache preparation is verified before each trial.

Clock starts at replica request and ends at the first accepted HTTP order. Fresh application processes in both conditions; Wasm components/providers are fetched/compiled afresh because the runtime has no persistent cache volume. Thus this compares node container-image caches, not persistent Wasm compilation caching or cold databases. Application/runtime images come from the local registry; the pinned Wasm NATS sidecar comes from Docker Hub, so its cold pull includes that network path. Pull policies and 5-second/4-second limits are unchanged. Java inventory schema/seed initialization is included. One extra worker exists at a time; all four Java pods share that worker.
