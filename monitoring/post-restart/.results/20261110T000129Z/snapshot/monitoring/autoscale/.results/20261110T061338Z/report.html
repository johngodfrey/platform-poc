Automatic CPU scaling: Java / Wasm

complete Pair 2: java

Shared benchmark controller, not Kubernetes HPA. CPU scale-in uses fresh 60-second CPU rates evaluated every 15 seconds. Target: 1.25 times each implementation’s median CPU over the last 30 seconds of warmup, minimum 0.05 core per capacity unit. CPU mode scales up at >110% target; both modes scale down at <70% average target sustained for 60 seconds. Missing signals reset the low-CPU hold. One automatic 1→2→1 cycle per trial, capped at two units. No load-phase timer issues scale commands.

Java adds one order-service pod; Wasm adds a whole runtime pod with providers/components, gated by a successful direct order before ingress admission. The CPU scopes and calibrated targets differ. Shared dependencies remain warm, images may be cached, resources and patched timeouts remain unchanged. This compares the configured policy/actuators; earlier trigger times do not prove a runtime starts faster.
